# 旋律回放与跟弹指引 四层设计（v1.4：按哼唱节奏连播 + 琴键顺序指引）

> 本质锚定：用户要的不是"看到一张静态的琴键图"，而是**在钢琴上重现自己的旋律**——回放（机器按你的节奏弹给你听）与跟弹（你照着提示亲手弹出来）是同一件事的两个方向：听→验证，做→内化。钢琴从"对照参照物"升级为"练习乐器"。

## 反常识根因（设计依据）

> 直觉做法是"把音符转成乐谱/五线谱让用户照着弹"，但对不懂乐理的小白，乐谱是新的门槛。正确做法是**让钢琴自己变成乐谱**：顺序气泡代替音符时值、脉冲高亮代替"当前小节"、点对前进代替读谱——知识不外授，直接长在界面上。

## 四层设计

| 层面 | 设计 |
|---|---|
| **数据规矩** | `SeqNote { midi, startSec, durSec }`（由 `Note.startSec/endSec` 直接导出——节奏真值来自哼唱切分，不量化不修正）；跟弹状态 `guideSeq/guideIdx` 封装在 PianoBoard 内部 |
| **数据存储** | 无持久化；全部会话内存态，重绘（换调/新分析）即复位 |
| **数据流转** | 回放：`player.playSequence(seq, onNote, onEnd)` 按原时序 setTimeout 调度标准音（误差 ~10ms 级，听感/视觉足够），逐音 `board.highlight` 高亮跟随；跟弹：`board.showGuide(midis, onDone)` 键上放序号气泡 `.gbadge`，指针键 `.guide` 脉冲，`advance(midi)` 点对前进/点错 `.wrong` 抖动，键位标签随当前调实时刷新（setKey 重绘后 `applyGuide()` 自动恢复） |
| **数据接口** | PianoPlayer 新增 `playSequence(): () => void`（返回停止函数）；PianoBoard 新增 `showGuide/guideIndex/guideActive/advance/clearGuide`；ui 新增状态 `seqStop/guideOn/guideTotal` 与 `stopSeq/exitGuide/updateGuideStatus`；domain/application **零改动** |

## 交互规则

- 结果区新增按钮行：「▶ 按你哼的节奏演奏」（播放中变「■ 停止演奏」）+「跟弹指引」（进行中变「退出跟弹」）+ 进度状态文本
- **互斥**：回放与跟弹互斥（启动一个先停另一个）；跟弹与「点琴键选 do」互斥（进跟弹自动取消勾选——点键语义只能有一个）
- 跟弹点键**先发声后判定**（不剥夺用户听觉反馈）；点错文案永远给提示不给批评（"亮着提示的键才是下一个"）
- 完成文案："全对！这段旋律（N 个音）你已经亲手弹出来了"——正向闭环
- 换调/重新哼唱 → 重绘 → 回放与跟弹自动复位（闭包不引用旧 DOM，无僵尸定时器）

## 验证

- I：30/30 回归保持绿、TSC-CLEAN、build 通过（纯新增，判定逻辑零改动）
- Q（人工）：示例音频 → 演奏：键位按时序逐个高亮、节奏与小星星一致；跟弹：气泡序号正确、点对前进/点错抖动、全点完出完成文案；回放中点「停止」立即静默；换调后气泡标签随新调刷新

## v1.5 增量：实时频率读数 + 音区自适应（用户反馈驱动）

| 反馈 | 根因 | 方案 |
|---|---|---|
| "画面上显示声音震动频率数值" | 频率只在内部流转，从未露出 | 两卡录音行加 `.hz` 读数位：有效帧实时显示 `Hz · 音名`（如 `196.0 Hz · G3`），midi 反推频率 440×2^((m−69)/12)；哼唱卡 live 改 true（canvas=null 只报数不画线） |
| "唱低音部分显示不出来，只显示最左第一个键" | PianoBoard 固定 C3–C6，超界音符 clamp 到边缘键——标签、气泡、高亮全部错位 | `setRange(low, high)`：按旋律 min/max ±2 半音扩展，边界对齐到 C，夹取 C1–C7；白键数动态计算、容器 overflow-x 横向滚动（min-width 36px/白键）；clamp 全部改用实例音区；draw 重绘后 applyGuide 自动恢复（沿用 v1.4 约定） |

- I 不变量：渲染音区只影响 interfaces 显示，domain 判定（音高/切分/调性）永远基于原始 midi——"显示跟着事实走，事实不跟着显示走"
