# 小白翻译与琴键对照模块 四层设计（v1.1：application/describe + infrastructure/piano-audio + interfaces/piano）

> 本质锚定：在"翻译器"的时空约束下，本轮的本质是**让被翻译者本人完成验证闭环**——琴键是参照物不是玩具，大白话是降低符号系统的阅读摩擦，二者都不改变判定逻辑（I 不变量：分析结果与 v1 逐字段一致）。

## 反常识根因（设计依据）

> 小白验证音准**不需要先懂乐理**，只需要 A/B 对比：直觉设计是"教用户看懂 do re mi 再验证"，实际有效的是"点一下听你哼的原声、再点一下琴键听标准音，耳朵自己裁决"。教学是结果，对比是路径。

## 三个能力（由本质展开）

| 能力 | 归属 | 说明 |
|---|---|---|
| 大白话翻译层 | `application/describe.ts` + `core/constants`（性格表） | 唱名性格表、旋律白话叙述、音域白话——纯文本生成，零 UI 依赖 |
| 琴键对照键盘 | `interfaces/piano.ts`（PianoBoard 组件） | C3–C6 三组八度；键上实时标注"你当前调的简谱数字"；点击高亮 |
| A/B 试听闭环 | `infrastructure/piano-audio.ts`（PianoPlayer） + ui 接线 | 点唱名 chip → 播放原哼片段；点琴键 → 播放标准音；勾选"点琴键选 do"→ 点击即重映射 |

## 四层设计

| 层面 | 设计 |
|---|---|
| **数据规范** | `SOLFEGE_PLAIN`（7 个唱名的性格白话，如 do="家，最稳的音"）；`labelForPitch(midi, base) → {symbol, degree, accidental} \| null`（琴键标签与 toSolfege 同源，单一映射表 DEGREE_MAP） |
| **数据存储** | 无持久化；`PianoPlayer` 懒创建独立 AudioContext（播放层与采集引擎解耦，互不管理生命周期）；原哼片段以 Float32Array(16k) 直接喂 `playBuffer()`（createBuffer 自动重采样） |
| **数据流转** | 分析完成 → 渲染琴键+标签 → [用户点 chip] 播放原声片段 / [用户点琴键] 播放标准音 → 勾选"选 do"时点击琴键触发 `rekey()` → 唱名线、琴键标签、大白话叙述同步重渲染（单一状态源：`lastResult` + `lastBuf`） |
| **数据接口** | `describeMelody(solfege, key): string`、`describeRange(vr): string`（纯函数）；`PianoBoard.render(el, opts)`、`setKey(basePc, mode)`、`highlight(midi)`、`onKeyClick(cb)`；`PianoPlayer.play(midi, durSec?)`、`playBuffer(buf, fromSec, toSec)` |

## 生命周期钩子

- `PianoPlayer`：懒 init（首次播放时创建 ctx）；`dispose()` 关闭 ctx（页面 beforeunload 调用）；与采集 AudioEngine 互不持有。
- `PianoBoard`：纯 DOM 组件，`destroy` = 移除节点；无定时器无泄漏。
- `describe.ts`：纯函数无状态。

## 大白话文案规范（规则层）

1. 禁止裸术语：MIDI/半音/音分 → "琴键数""低了 X 音分（约三分之一度）"配动作建议（"稍微唱高一点点"）。
2. 唱名一律带性格：`1 do（家，最稳的音）`。
3. 每步操作文案回答"我现在该干什么"，不解释原理。
4. 判定结果永远给"下一步"：主音不确定 → "点你觉得像 do 的琴键试试"。

## 验证

- Q：`labelForPitch` 与 `toSolfege` 同一映射表（同输入同标签）；`describeMelody` 叙述含结尾落点与主音。
- I：v1 全部 11 项回归不变（判定逻辑零改动）；PianoPlayer/PianoBoard 不触碰分析管线。
