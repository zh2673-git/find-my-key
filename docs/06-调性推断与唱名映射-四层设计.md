# 调性推断与唱名映射模块 四层设计（domain/tonality + domain/solfege）

> 本质锚定：在"翻译器"的时空约束下，本模块的本质是**推断"你把哪个音当 do"，并把旋律形状翻译成首调唱名**——这是翻译器的翻译动作本体。

## 数据规范

- 输出 `KeyCandidate{tonicPc: 0..11, mode: 'major'|'minor', score}` top3 降序。
- 输出 `SolfegeNote{degree: 1..7, accidental: -1|0|1, octaveShift: -2..2, symbol, midi, startSec, endSec, cents}`。
- 唱名映射表（rel = (pc − base) mod 12 → [度数, 变化音]）：
  `0→1, 1→♭2, 2→2, 3→♭3, 4→3, 5→4, 6→♯4, 7→5, 8→♭6, 9→6, 10→♭7, 11→7`。
- **小调路由**（中国简谱惯例：小调以 la 为基调）：base = 相对大调主音 = (tonicPc + 3) mod 12，旋律主音呈现为 **6**。

## 数据存储

无持久化；`KS_PROFILES`（大/小调 Krumhansl-Kessler 画像）与 `SCALE_TEMPLATES` 为规范层常量（core/constants）。

## 数据流转（三重证据打分 + 锚定消歧）

调性打分：`score = 0.5×覆盖率 + 0.3×KS相关性 + 0.2×锚定分`

1. **覆盖率**：时长加权音级直方图落在大/小调音阶 7 个音级内的比例。
2. **KS 相关性**：直方图与 KK 画像（按主音旋转）的 Pearson 相关。
3. **锚定分**（消歧关键）：0.7×尾音 + 0.3×首音；音级相对主音为 主音→1、属音→0.6、三音→0.3、其他→0。
   - 反常识依据：短旋律对"相对大小调/五度圈邻调"天然二义（C 大调与 G 大调覆盖率同为 1.0），但**哼唱习惯上旋律开头常从主音出发、结尾常落回主音/属音**——首尾音是最强先验。

唱名映射：逐音符 `snapped = round(midi)` → rel → 查表；八度点 `octaveShift = clamp(round((midi − 全曲中位 midi)/12), −2, 2)`（以"全曲重心"为中央八度参照）。

## 数据接口

```ts
export function inferKey(notes: Note[]): KeyCandidate[]            // top3
export function toSolfege(notes: Note[], key: KeyCandidate): SolfegeNote[]
```

## 生命周期钩子

纯函数无状态。`rekey`（application 层）复用 `toSolfege`：主音切换只重算映射、**绝不重算切分**（I 不变量）。

## 验证

C 大调音阶→C 大调 top1；小星星 G 大调→G 大调 top1（属音结尾+主音开头锚定胜出相对调）；同旋律 −12 半音→唱名序列完全不变（首调不变性）；a 小调旋律→以 6 为基调的唱名。
