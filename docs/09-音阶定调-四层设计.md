# 音阶定调模块 四层设计（v1.2：domain/scale-match + application/analyzeScale + 校准卡双模式）

> 本质锚定：音阶唱名自带**语义锚点**——唱"1"的那个音就是用户心中的 do。滑音测的是物理跨度（能唱多宽），音阶测的是音乐锚点（do 在哪）+ 相对音准（哪个音唱偏了）。二者互补不互斥，故做成双模式而非替换。

## 反常识根因（设计依据）

> 直觉设计是"从哼唱里推断调"（v1 做法从头到尾都是猜），更科学的是**让用户唱出带语义的音阶直接报出 do**——判定从"猜"变成"读"。但唱音阶测不了音域跨度，所以滑音模式必须保留。

## 四层设计

| 层面 | 设计 |
|---|---|
| **数据规范** | `ScaleMatch { ok, tonicPc, hit, total, deviants: {index, semitones}[], steps: {index, semitones}[] \| null }`；错误码 `SCALE_TOO_SHORT`（音符 <5 拒判） |
| **数据存储** | 无持久化（判定成功后由用户显式点「设为我的调」→ 走 v1.1.1 MyKeyStore） |
| **数据流转** | 唱音阶 → trackPitch → segmentNotes → matchScale：①12 个候选主音逐个投票（每个音相对候选主音折叠 mod 12，找最近大调音级，命中最多、总偏差最小者胜——对漏音/重复/跑偏稳健）；②音符数恰为 8 时步进对齐模板 [2,2,1,2,2,2,1]，逐步偏差指出"哪个音唱高/低了几个琴键" |
| **数据接口** | `matchScale(notes): ScaleMatch`（domain 纯函数）；`analyzeScale(buf): ScaleMatch`（application 用例）；UI `renderScaleMatch(m, el)` + 模式切换 `setCalMode('scale'\|'gliss')` |

## 判定规则

- `ok = 命中音级比例 ≥ 0.8`：跑偏一两个音仍可定调（小白唱不全是常态），但点名偏差
- 步进对齐仅在音符数恰为 8 时启用（少一个音就无法逐位比对，宁缺毋滥）
- 不做自动纠偏：整段唱低半音 → do 判为实际音高的主音（跟随实测，I 不变量：判定只依赖录音事实）

## 大白话文案规范

- 定调成功 → "你心中的 do，就是钢琴上的 X 键（X 大调）" + 下一步「设为我的调」
- 偏差用"琴键"表述："高了约 1 个琴键 / 半个琴键"，绝不出现"半音/音分"
- 失败永远给行动："慢一点，从「do」开始一个音一个音唱；或换滑音模式"

## 验证

- Q：C 大调合成音阶 → do=C 全命中零步偏；G 起音音阶 → do=G；3 音 → SCALE_TOO_SHORT；mi 唱成 fa → do 仍 C 且步进点名 +1；整段低半音 → do=B
- I：v1/v1.1/v1.1.1 全部回归保持绿（判定逻辑零改动，纯新增模块）
