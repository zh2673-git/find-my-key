# 找调儿 FindMyKey 项目方案

> 生成时间：2026-10-02 | 语言：TypeScript（Web） | 模式：生产模式

## 项目目标

一个"能哼出曲子但不懂乐理"的人，打开网页即可：

1. **找调**：对着麦克风从最低哼到最高（约 8 秒滑音），系统测出**舒适音域**与**推荐主音区间**（"你的 do 可以落在哪几个音上"）。
2. **翻译**：哼一段旋律（≤15 秒），系统输出**简谱数字 + do re mi 唱名**（首调 movable-do，含八度点、变化音 ♯/♭、音分偏差提示），主音不确定时可手动切换重新映射。

**一句话点破**：唱名不需要绝对音感，只需要旋律的形状——本工具提取哼唱的"旋律形状"（相对音程序列），再推断你把哪个音当 do。

**系统边界（不做什么）**：不做多音轨/合唱识别，不做录音棚级 MIDI 转录（Melodyne 的领域），不做曲库检索（SoundHound 的领域），不做社交/评分。

## 本质定义（时空契约校验）

> **本质定义**：找调儿是一个**把"你的嗓音"和"你的哼唱"翻译进首调唱名符号系统的双向翻译器**——找调是把声带这件"乐器"的舒适区翻译成主音坐标；翻译是把旋律的"形状"（相对音程）翻译成唱名序列。它的成立前提是一个物理事实：**哼唱的绝对音高会漂移，但旋律的音程形状稳定**，而唱名系统本身就是相对系统，二者同构。

- **时空契约校验**：
  - **空间归属**：音频帧缓冲由 runtime 层（AudioEngine）独占并在 destroy 时按逆序回收；分析产物（音高轨迹/音符列表/调性候选/唱名序列）归 application 会话状态所有，UI 只读；录音不持久化不上传，导出仅显式触发。
  - **时间流形态**：**事件循环 + 顺序管道混合**——AudioWorklet 回调推帧（事件循环/消息泵），单次分析用例内部为严格顺序管道（采集→F0 跟踪→音符切分→调性推断→唱名映射），UI 为响应式状态流。
  - **规则拦截**：编译时由 TypeScript 类型系统拦截（域层纯函数签名即契约）；运行时以 `DomainError` 拦截数值越界（NaN、空音符序列、音域过窄、非人声输入），并向上映射为用户可读提示。

## 架构总览（第0级时空映射）

| 时空层级 | 本项目对应 | 物理目录 | 核心职责（时空视角） |
|---------|----------|---------|-------------------|
| 数据规范（规则） | 类型/常量/错误码/合成器 | `src/core/` | 定义所有内存布局与类型规则（Note、KeyCandidate、唱名表、KK 音阶画像），零依赖 |
| 数据存储（空间） | 麦克风流/音频帧缓冲/WAV（预留） | `src/infrastructure/` | getUserMedia、AudioWorklet 采集器；空间落地与回收 |
| 流转-规则（业务时空） | 纯算法域 | `src/domain/` | YIN 音高跟踪、音符切分、调性推断、唱名映射、音域分析——**纯函数，无 IO** |
| 流转-编排（调度时空） | 会话状态机与用例 | `src/application/` | 校准用例、翻译用例、演示用例、主音切换重映射、实时音高句柄 |
| 运行时（时空管家） | 音频引擎生命周期 | `src/runtime/` | init（开辟 AudioContext+Worklet 空间）/ start（启动采集消息泵）/ stop（断链回收流）/ destroy（逆序关闭，防泄漏） |
| 数据接口（时空入口） | 单页 UI | `src/interfaces/` + `index.html` | 按钮事件→用例调用；渲染音域图、唱名时间线、调性选择器 |

**依赖铁律**：`interfaces → application → domain ← infrastructure`；`runtime` 编排生命周期；`domain` 纯函数不依赖任何 IO（这是 I 不变量可测性的根基）。

## 模块递归四层设计（概要，钩子强制）

每个模块的详细四层设计见 04~07 文档。第 1 层模块清单：

| 模块 | 本质（锚定父本质） | 生命周期钩子 |
|------|------------------|-------------|
| 音高跟踪 pitch-track | 从音频帧中提取"旋律形状"的原料：F0 时间序列 | 纯函数无状态（init/destroy = 无操作，以"无共享可变状态"声明替代） |
| 音符切分 note-segment | 把 F0 曲线切成"音符"离散单元（空间离散化） | 同上 |
| 调性推断与唱名映射 tonality | 推断"你把哪个音当 do"，并把形状翻译成首调唱名 | 同上 |
| 音域校准 voice-range | 把滑音轨迹翻译成舒适音域与主音区间 | 同上 |

- `runtime`（AudioEngine）显式实现 `init/start/stop/destroy`（唯一有状态生命周期模块，见 02-架构设计 §3）。
- `infrastructure`（capture-worklet）在 worklet 线程内独立缓冲，主线程侧缓冲由 runtime 持有并随 stop 回收。
- `application`（session）持有分析会话状态（单一状态源），UI 不持有业务状态。

## 验证方式

前置 P（浏览器能力 + 麦克风权限 + 人声输入）→ 后置 Q（合成音频回归：音阶/小星星/低八度不变性/小调/滑音音域，判定值见 program.md）→ 不变量 I（纯函数可复现、唱名值域有界、生命周期无泄漏）。纯工具产品，无 `validate_llm()` 维度。

## 项目愿景

阶段 1 解决"翻译"（哼唱→唱名、嗓音→key）。视角升级后，真正的产品是**你的个人乐理坐标系**：一旦系统知道你的 key 与哼唱习惯，它可以把任何一首歌"翻译进你的调"、生成你唱得舒服的简谱、并进一步直出乐器指法（尤克里里和弦位/钢琴键位）、实时跟唱纠偏、哼唱搜歌入门——它将成为"会哼歌"与"会乐器"之间的协议层。判断本品类创新是否成立的标准不是功能多寡，而是**哼唱与乐理符号之间的翻译摩擦有多小**。
